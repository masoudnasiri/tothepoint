# برگه مطالعه فنی برای مالک محصول

زبان ساده و مدیریتی. امشب همین را بخوانید.

## ۱. Rivar در یک جمله چیست؟

سامانه تصمیم‌یار تأمین پروژه‌ای و بهینه‌سازی نقدینگی که به سازمان کمک می‌کند از بین گزینه‌های تأمین، با قید بودجه و زمان، انتخاب قابل دفاع بسازد.

## ۲. تفاوت با اکسل و ثبت اطلاعات ساده چیست؟

اکسل ثبت می‌کند. Rivar فرآیند دارد: نهایی‌سازی، تخصیص کارشناس، گزینه تأمین، پوشش قطعه، حل بهینه‌سازی، تصمیم، و اثر مالی. قواعد در سرور اعمال می‌شوند، نه فقط در فایل شخصی.

## ۳. معماری کلی چیست؟

سه جزء در Docker: رابط کاربری، API، پایگاه داده. کاربر از مرورگر وارد می‌شود، API با توکن کار می‌کند، داده در PostgreSQL می‌ماند.

## ۴. Backend چیست و اینجا چه می‌کند؟

برنامه سرور. ورود، قواعد کسب‌وکار، ذخیره داده، اجرای بهینه‌سازی، گزارش. فایل ورود: `backend/app/main.py`.

## ۵. Frontend چیست و اینجا چه می‌کند؟

صفحات محصول که کاربر می‌بیند. با React ساخته شده و به API وصل است. فایل مسیرها: `frontend/src/App.tsx`.

## ۶. Database چیست و چه نگه می‌دارد؟

PostgreSQL. پروژه، قلم، تأمین‌کننده، گزینه، بسته، تصمیم، بودجه، فاکتور، پرداخت، ممیزی.

## ۷. API چیست و چرا مهم است؟

قرارداد رسمی بین صفحه و سرور. ارزیاب می‌تواند همان قابلیت را بدون UI با `/health` و `/openapi.json` ببیند.

## ۸. Docker چیست و چرا استفاده شده؟

بسته‌بندی اجرای محصول. سه سرویس با یک فرمان بالا می‌آیند. وابستگی «روی لپ‌تاپ من کار می‌کند» کمتر می‌شود.

## ۹. PostgreSQL چیست و چرا سازمانی است؟

پایگاه رابطه‌ای پایدار با قید و تراکنش. برای داده تأمین و مالی که نباید گم شود مناسب است. داده روی volume جدا از کانتینر است.

## ۱۰. ORM / SQLAlchemy چیست؟

لایه برنامه برای حرف زدن با جداول، بدون نوشتن همه SQLها دستی. مدل‌ها در `backend/app/models.py` هستند.

## ۱۱. FastAPI چیست؟

چارچوب ساخت API در Python. مستند OpenAPI را خودش می‌سازد. برای نمایش زنده `/openapi.json` مفید است.

## ۱۲. React چیست؟

کتابخانه ساخت رابط کاربری. صفحات داشبورد، تأمین، بهینه‌سازی و مالی با آن ساخته شده‌اند.

## ۱۳. تست‌ها چه چیزی را اثبات می‌کنند و چه چیزی را نه؟

اثبات می‌کنند بخش‌هایی از منطق در شرایط کنترل‌شده درست کار کرده‌اند. اثبات نمی‌کنند کل محصول بدون نقص است. الان suite کامل به‌خاطر یک import ناقص در تست تصویر مالی قطع می‌شود.

## ۱۴. Optimization دقیقاً یعنی چه؟

انتخاب ترکیب گزینه‌های تأمین با قیدهایی مثل بودجه و زمان، توسط حل‌کننده OR-Tools. گزارش مدیریتی تنها نیست؛ یک مسئله بهینه‌سازی حل می‌شود.

## ۱۵. Package / Sub-item یعنی چه؟

خیلی از تجهیزات IT یک دستگاه نیستند؛ از قطعه تشکیل می‌شوند. بسته یعنی تأمین‌کننده چه بخشی از آن قطعات را می‌دهد: کامل یا جزئی.

## ۱۶. Coverage یعنی چه؟

آیا مجموع بسته‌ها همه قطعات لازم را پوشش می‌دهد یا جا خالی می‌ماند.

## ۱۷. چرا lock coverage مهم است؟

اگر پوشش ناقص را قفل کنید، تصمیم اجرایی روی چیزی گرفته‌اید که هنوز قابل تأمین کامل نیست. کد این را می‌تواند مسدود کند؛ روی این سرور پیش‌فرض با flag خاموش است.

## ۱۸. Cashflow چطور ساخته می‌شود؟

از تاریخ و مبلغ فاکتور، دریافت، پرداخت تأمین‌کننده و بودجه دوره‌ای. داشبورد این‌ها را روی زمان نشان می‌دهد.

## ۱۹. Audit log چه نقشی دارد؟

نشان می‌دهد چه کسی چه کاری کرده؛ مثلاً ورود. برای ارزیابی دانش‌بنیان یعنی ردپا، نه فقط حرف.

## ۲۰. Backup/update safety چرا مهم است؟

محصول سازمانی نباید با یک به‌روزرسانی داده را از دست بدهد. volume جدا و اسکریپت backup برای همین است. `docker compose down -v` داده را پاک می‌کند.

## ۲۱. چه چیزهایی را نباید بیش از حد ادعا کنیم؟

- اینکه محصول ERP یا حسابداری کامل است
- اینکه همه APIها الان با RBAC ریزدانه اجباری‌اند
- اینکه lock پوشش ناقص حتماً در UI همین سرور بدون flag کار می‌کند
- اینکه PuLP موتور بهینه‌سازی است
- اینکه برند در تمام اسکریپت‌ها و نام دیتابیس عوض شده
- اینکه تست کامل سبز است
- اینکه ویدیو یا اسلاید جای دمو زنده را می‌گیرد

## ۲۲. محدودیت‌های فعلی چیست؟

- نسخه pilot / RC1
- Frontend این استک با dev server بالا است
- لینک مستقیم بعضی صفحات ممکن است 404 بدهد
- دمو ۱۴۰۵ تصمیم‌ها را lock نکرده
- router تصویر مالی جدا سوار نشده
- نرخ ارز جدا موقتاً غیرفعال است
- نام قدیمی PDSS در بعضی پوشه‌ها مانده

# آمادگی داده دمو برای جلسه ارزیابی

تاریخ بررسی: ۱۷ اوت ۲۰۲۶  
اسکریپت: `backend/scripts/create_it_procurement_demo_1405.py`  
پیشوند: `DEMO_IT_1405_`  
گزارش قبلی: `docs/restart-audit/32_it_demo_data_1405_feed_report.md`

## نتیجه کوتاه

اسکریپت **پیدا شد** و دیتاست روی سرور زنده **موجود است**.  
برای فردا **کافی است**، با این شرط که مسیر تحویل/فاکتور یا از یک تصمیم قفل‌شده زنده ساخته شود یا از API/کد نشان داده شود.

`cleanup` اجرا نشده و نباید قبل از جلسه اجرا شود.

## اسکریپت

| مورد | وضعیت |
| --- | --- |
| اسکریپت دمو IT ۱۴۰۵ | found |
| مسیر | `backend/scripts/create_it_procurement_demo_1405.py` |
| حالت‌ها | `create` / `verify` / `cleanup` |
| وابستگی به `DEMO_RC8_` یا `PH5` | ندارد |

دستور بررسی بدون تغییر داده:

```bash
cd /root/pdss
docker compose run --rm -e PYTHONPATH=/app backend python scripts/create_it_procurement_demo_1405.py --mode verify
```

اگر دیتاست خالی شد (فقط در اضطرار):

```bash
docker compose exec -T -e PYTHONPATH=/app backend python scripts/create_it_procurement_demo_1405.py --mode create --skip-pre-clean
```

`create` بدون `--skip-pre-clean` ابتدا همان پیشوند را پاک و دوباره می‌سازد. در جلسه این کار را نکنید مگر دیتاست واقعاً خراب شده باشد.

## آیا برای فردا کافی است؟

**بله، برای مسیر اصلی ارزیابی کافی است:**

1. ورود و نقش‌ها
2. پروژه IT و اقلام پایه/زیرقلم
3. نهایی‌سازی و تخصیص تأمین
4. تأمین‌کننده متمایز و گزینه/بسته
5. coverage کامل و ناقص
6. ورود به بهینه‌سازی و کمبود مهر ۱۴۰۵
7. داشبورد/گزارش/ممیزی روی داده موجود

**ناکافی برای ادعای «کل سبد از قبل قفل و فاکتور شده»:**

- تصمیم‌ها عمداً lock نشده‌اند
- برنامه تأمین، تأیید تحویل، پذیرش PM، فاکتور و پرداخت به داده قفل‌شده نیاز دارند
- رویداد نقدینگی کامل بعد از فاکتور/پرداخت ساخته می‌شود؛ بودجه دوره‌ای از قبل هست

## چه چیزی کم است؟

| کمبود | اثر روی جلسه | کار پیشنهادی |
| --- | --- | --- |
| تصمیم قفل‌شده انبوه | plan/تحویل/فاکتور از روی دمو آماده نیست | یک تصمیم را زنده lock کنید یا از API/کد نشان دهید |
| فاکتور و پرداخت دمو | اثر کامل cashflow از invoice دیده نمی‌شود | یک فاکتور زنده بسازید یا API را نشان دهید |
| run بهینه‌سازی ذخیره‌شده | لیست run ممکن است خالی باشد | یک optimize زنده اجرا کنید |
| deep-link SPA | `/dashboard` مستقیم ممکن است 404 بدهد | از `/` و منو وارد شوید |

## کارهای ممنوع قبل از جلسه

- `--mode cleanup`
- `docker compose down -v`
- reset دیتابیس
- پاک کردن کاربران بذر
- commit کردن dump یا لاگ حاوی رمز

## حکم آمادگی داده

**ready** برای نمایش هویت محصول، گردش تأمین، پوشش بسته، بهینه‌سازی و استقرار.  
**partial** برای مسیر پس از lock (برنامه تأمین، تحویل، فاکتور، پرداخت تأمین‌کننده).
